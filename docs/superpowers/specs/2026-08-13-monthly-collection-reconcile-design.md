# กระทบยอดการเก็บเงินรายเดือนจากไฟล์ Excel

วันที่: 2026-08-13
สถานะ: รออนุมัติก่อนทำแผน implementation

## 1. ปัญหา

การเงินเก็บเงินสงเคราะห์รายเดือนโดยดาวน์โหลดรายชื่อสมาชิกออกมาเป็นไฟล์ ไปเก็บเงินจริง แล้วอัปโหลด
กลับเข้าระบบเพื่อบันทึกว่าใครชำระแล้ว ระบบตรวจไฟล์ทิศทางเดียว — ตรวจว่าแถวในไฟล์ตรงกับสมาชิกใน
ระบบหรือไม่ แต่ **ไม่เคยตรวจทิศกลับกันว่าสมาชิกที่ควรถูกเก็บเงินงวดนั้น คนไหนหายไปจากไฟล์**

ผลคือถ้าแถวตกหล่นจากไฟล์ (ลบทิ้ง คัดลอกไม่ครบ ส่งไฟล์เก่า) ระบบจะรับไฟล์นั้นแบบผ่านฉลุยโดยไม่เตือน
อะไรเลย คนที่หายไปจะเงียบอยู่ในสถานะยังไม่ชำระจนกว่าจะมีคนไปไล่ดูเอง

## 2. เป้าหมาย

หลังอัปโหลดไฟล์ ระบบต้องบอกได้ทันทีว่า **งวดนี้ขาดใครบ้าง** พร้อมเหตุผล และให้ผู้ใช้จัดการต่อได้
โดยไม่ต้องออกจากหน้าจอ

## 3. สิ่งที่มีอยู่แล้ว (baseline)

### บั๊กของเดิมที่ต้องแก้ไปพร้อมกัน

1. **รับ .xlsx แต่อ่านไม่ได้จริง** — หน้าจอยอมรับ `.xlsx/.xls` (`matrix/page.tsx:416`) แต่ parse ด้วย
   `file.text()` + `split(',')` (`:424-441`) ไฟล์ .xlsx เป็น ZIP ไบนารี จึงได้ข้อมูลขยะส่งขึ้น API
   โดยไม่มีข้อความเตือน
2. **ปุ่ม "ดาวน์โหลด Template" ออกไฟล์ .csv** (`:395-399`) ไม่ใช่ Excel ตามชื่อปุ่ม
3. **`errors[]` ไม่เคยขึ้นหน้าจอ** — ถูก `console.error` ทิ้ง (`:458`) ผู้ใช้ไม่รู้ว่าแถวไหนล้มเหลว
4. **Template ตกหล่นสมาชิกที่ไม่ได้หักเงินเดือน** — คนที่จ่ายสดไม่เคยอยู่ในไฟล์ จึงเก็บเงินไม่ครบตั้งแต่ต้นทาง

## 4. ขอบเขต

**ทำในรอบนี้**

- ตรวจย้อนว่าใครหายจากไฟล์ และใครอยู่ในไฟล์แต่ยังไม่ชำระ
- ย้ายการ parse ไฟล์ไปฝั่ง server รองรับ .xlsx/.xls/.csv จริง
- Template เป็น .xlsx จริง และรวมสมาชิกที่ยังมีสภาพทุกคน
- แผงผลการกระทบยอดบนหน้าจอ + ดาวน์โหลดรายชื่อที่ขาดเป็น .xlsx
- บันทึกค้างชำระอัตโนมัติเฉพาะคนที่ขาด
- ปุ่มแจ้งเตือนค้างชำระแบบต้องกดยืนยันเอง

**ไม่ทำในรอบนี้**

- เก็บประวัติผลการกระทบยอดลงฐานข้อมูล (เหตุผลในข้อ 5.5)
- แจ้งเตือนผ่าน SMS/อีเมล/LINE
- อัปโหลดหลายงวดพร้อมกันในไฟล์เดียว

## 5. การออกแบบ

### 5.1 ขอบเขตการเทียบ

ความเสี่ยงหลักคือไฟล์ที่ครอบคลุมไม่ครบทั้งอำเภอ ถ้าเทียบกับสมาชิกทั้งหมดเสมอ การเงินโรงเรียนเดียว
ที่อัปโหลดไฟล์ 40 คน จะได้รายงานว่าขาดอีก 560 คน และถูก mark ค้างชำระทั้งหมด

กติกา:

1. หาโรงเรียนของทุกแถวในไฟล์ (ผ่าน `memberNo` → `member.schoolId`) ได้เป็น `schoolIdsInFile`
2. `expected` = สมาชิกที่ `status ∈ {ACTIVE, ARREARS}` และ `schoolId ∈ schoolIdsInFile`
3. ถ้าผู้ใช้ติ๊ก `fullDistrict = true` → `expected` = สมาชิก `ACTIVE|ARREARS` ทุกโรงเรียน
   (ใช้เมื่อไฟล์คือรายชื่อครบทั้งอำเภอ จะได้เห็นกรณีที่หายทั้งโรงเรียน)
4. ตัดซ้ำด้วย `SchoolScopeService.resolveSchoolId(actor)` เสมอเป็นด่านสุดท้าย — ผู้ใช้ระดับ
   `SCHOOL_ADMIN` ส่ง `fullDistrict = true` มาก็ยังถูกจำกัดที่โรงเรียนตัวเอง ห้ามเชื่อค่าจาก client

### 5.2 การจำแนกผลลัพธ์

| กอง | นิยาม | ลงฐานข้อมูล |
|---|---|---|
| `paid` | อยู่ในไฟล์ + สถานะชำระแล้ว | บันทึกชำระ + ออกใบเสร็จ (พฤติกรรมเดิม) |
| `alreadyPaid` | ชำระอยู่ก่อนอัปโหลดแล้ว | ไม่ทำอะไร ไม่นับเป็นขาด |
| `missing` / `NOT_IN_FILE` | อยู่ใน `expected` แต่ไม่มีเลขสมาชิกนี้ในไฟล์ | ตั้ง `isArrears` ถ้าเปิด auto |
| `missing` / `IN_FILE_NOT_PAID` | อยู่ในไฟล์ แต่สถานะไม่ใช่ชำระแล้ว | ตั้ง `isArrears` ถ้าเปิด auto |
| `unknown` | มีในไฟล์ แต่หา `memberNo` ในระบบไม่เจอ | ไม่ทำอะไร รายงานพร้อมเลขบรรทัด |

### 5.3 API

**`POST /contributions/upload`** — รับ `multipart/form-data`

| field | ชนิด | ค่าเริ่มต้น | ความหมาย |
|---|---|---|---|
| `file` | ไฟล์ | – | .xlsx / .xls / .csv |
| `year`, `month` | number | – | งวดที่ต้องการบันทึก |
| `fullDistrict` | boolean | `false` | ไฟล์นี้คือรายชื่อครบทั้งอำเภอ |
| `autoMarkArrears` | boolean | `true` | ตั้งธงค้างชำระให้คนที่ขาด |

ยังคงรองรับ body JSON `{ year, month, data[] }` แบบเดิมต่อไป เพื่อไม่ให้ของที่เรียกอยู่พัง

Response:

```jsonc
{
  "scope": { "fullDistrict": false, "schools": [{ "id": "…", "code": "…", "name": "…" }] },
  "summary": {
    "expected": 42, "paid": 38, "alreadyPaid": 1,
    "missingFromFile": 2, "inFileNotPaid": 1, "unknownInFile": 0, "markedArrears": 3
  },
  "missing": [
    { "memberNo": "M0123", "fullName": "…", "schoolCode": "…", "schoolName": "…",
      "groupName": "…", "amountDue": 100, "reason": "NOT_IN_FILE" }
  ],
  "unknown": [{ "rowNo": 17, "memberNo": "M9999" }],
  "success": 38, "failed": 0, "notFound": 0, "errors": []
}
```

สี่ field สุดท้ายคงไว้เพื่อความเข้ากันได้กับหน้าจอปัจจุบันที่อ่าน `response.data.success` และ
`response.data.errors`

**`GET /contributions/template`** — ออก .xlsx จริง (`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)
คืน JSON เดิมเมื่อส่ง `?format=json` และรวมสมาชิก `ACTIVE|ARREARS` ทุกคน ไม่กรอง `salaryDeduction`
โดยเพิ่มคอลัมน์ `วิธีชำระ` (หักเงินเดือน / จ่ายเอง) เพื่อให้ผู้เก็บเงินแยกได้

**`POST /contributions/periods/:id/missing/export`** — client ส่ง body `{ missing: MissingRow[] }`
คือรายการที่เพิ่งได้จาก response ของ upload กลับขึ้นมา ส่งกลับเป็นไฟล์ .xlsx สำหรับส่งต่อให้โรงเรียน
ตามเก็บ (ใช้ POST เพราะรายการยาวเกินจะใส่ query string และผลไม่ได้เก็บไว้ฝั่ง server ตามข้อ 5.5)
server ตรวจซ้ำว่าทุก `memberNo` ในรายการอยู่ในขอบเขตโรงเรียนของผู้ใช้ก่อนสร้างไฟล์

ทุก endpoint คง `@Roles(ADMIN, SCHOOL_ADMIN, FINANCE)` และ `assertPeriodOpen` ตามของเดิม

### 5.4 การ parse ไฟล์

ย้ายมาฝั่ง server ด้วย `xlsx@^0.18.5` ที่มีอยู่แล้วใน `apps/api/package.json:73` เหตุผล: ฝั่งเว็บไม่ต้อง
แบก dependency เพิ่ม และรองรับสามนามสกุลที่จุดเดียว แยกเป็น `PaymentFileParser` เพื่อทดสอบแยกได้

- อ่าน sheet แรก แปลงเป็น array of object โดยใช้แถวแรกเป็น header
- ต้องมีคอลัมน์ `เลขสมาชิก` ไม่งั้นโยน `BadRequestException` พร้อมบอกว่าเจอ header อะไรบ้าง
- แถวว่างข้าม ไม่นับเป็น error
- ค่า `สถานะ` ที่ถือว่าชำระแล้ว: `ชำระแล้ว`, `ชำระ`, `paid` (ตามที่โค้ดเดิมรับ `contributions.service.ts:1119`)
- เก็บเลขบรรทัดจริงในไฟล์ติดไปกับทุกแถว เพื่อรายงานกลับได้ว่าแถวไหนมีปัญหา
- `เลขสมาชิก` ซ้ำกันหลายแถว: ใช้แถวแรกที่มีสถานะชำระแล้ว ถ้าไม่มีเลยใช้แถวแรกสุด และรายงานทุกแถวที่
  ซ้ำเข้า `errors` พร้อมเลขบรรทัด เพื่อให้ผู้ใช้กลับไปแก้ไฟล์ต้นทาง — ห้ามบันทึกชำระซ้ำสองครั้ง

### 5.5 การบันทึกค้างชำระและการแจ้งเตือน

**อัตโนมัติได้**: ตั้ง `isArrears = true` เฉพาะ contribution ของคนใน `missing` — ต้องเขียน update
ที่ระบุ `memberId` ชัดเจน **ห้ามเรียก `markArrearsForPeriod` ตรง ๆ** เพราะตัวนั้นเหมารวมทุกคนที่ยังไม่
จ่ายทั้งงวดในขอบเขตโรงเรียนของผู้ใช้ (`contributions.service.ts:550`) ซึ่งกว้างกว่าที่ไฟล์ครอบคลุม
ธงนี้ย้อนกลับได้และไม่แตะสถานะสมาชิก

**ต้องกดเอง**: การแจ้งเตือนค้างชำระใช้ `sendArrearsNoticeForPeriod` ซึ่งเรียก
`processArrearsAfterNotice` ต่อ และตัดสมาชิกภาพได้จริง (`contributions.service.ts:569-574`)
จึงต้องเป็นปุ่มแยกที่ผู้ใช้กดหลังตรวจรายชื่อแล้ว พร้อม dialog ยืนยันที่ระบุจำนวนคนที่จะถูกตัดสมาชิกภาพ
ห้ามผูกให้ทำงานอัตโนมัติต่อท้ายการอัปโหลด เพราะไฟล์ที่อัปผิดครั้งเดียวจะตัดสมาชิกภาพคนหลายสิบคน

**ไม่เก็บผลการกระทบยอดลงฐานข้อมูล**: หลังอัปโหลดเสร็จ ทั้ง `NOT_IN_FILE` และ `IN_FILE_NOT_PAID`
เหลือสถานะเดียวกันในฐานข้อมูลคือยังไม่ชำระ การเพิ่มตารางใหม่เพื่อเก็บความต่างนี้ไม่คุ้มกับที่ได้
ผู้ใช้ที่ต้องการหลักฐานให้กดดาวน์โหลด .xlsx เก็บไว้

### 5.6 หน้าจอ

อยู่บนหน้า `contributions/matrix` เดิม

```
เลือกปี/เดือน
  ├─ [ดาวน์โหลด Template .xlsx]
  └─ [อัปโหลดไฟล์เก็บเงิน] → modal
        • เลือกไฟล์ (.xlsx / .xls / .csv)
        • ☑ บันทึกค้างชำระอัตโนมัติ
        • ☐ ไฟล์นี้คือรายชื่อครบทั้งอำเภอ   (แสดงเฉพาะ ADMIN / FINANCE)
        └─ [ตรวจสอบและบันทึก] → แผงผลการกระทบยอด
```

แผงผลการกระทบยอด:

- แถบสรุปสี่ตัวเลข: ต้องเก็บ / เก็บได้ / ขาด / ไม่รู้จัก
- แถบเตือนสีส้มเมื่อ `missing > 0`: `⚠️ ขาด N คน — ตรวจรายชื่อด้านล่างก่อนปิดงวด`
- ตารางรายชื่อที่ขาด จัดกลุ่มตามโรงเรียน พับเก็บได้ คอลัมน์: เลขสมาชิก, ชื่อ-สกุล, กลุ่มเก็บเงิน,
  ยอด, badge เหตุผล (`ไม่มีในไฟล์` สีแดง / `อยู่ในไฟล์ แต่ยังไม่ชำระ` สีเหลือง)
- ตารางไม่รู้จักในระบบ แสดงเลขบรรทัดในไฟล์
- `errors[]` แสดงบนจอ ไม่ใช่ `console.error`
- ปุ่ม [ดาวน์โหลดรายชื่อที่ขาด .xlsx]
- ปุ่ม [แจ้งเตือนค้างชำระ] พร้อม dialog ยืนยัน

ผลการกระทบยอดเก็บใน state ของหน้าจอ ไม่ persist — refresh แล้วหาย ตามที่ตัดสินใจในข้อ 5.5
ใช้ `react-toastify` สำหรับ feedback ตามแนวทางของโปรเจกต์ วันที่บนหน้าจอแสดงเป็น พ.ศ.

## 6. ความปลอดภัยและสิทธิ์

- `@Roles(ADMIN, SCHOOL_ADMIN, FINANCE)` เหมือนของเดิม
- `SchoolScopeService.resolveSchoolId(actor)` เป็นด่านสุดท้ายเสมอ ทั้งตอนคำนวณ `expected`
  ตอน mark arrears และตอน export
- แถวที่ผู้ใช้ไม่มีสิทธิ์ในโรงเรียนนั้นยังคงเข้ากอง `errors` เหมือนเดิม (`contributions.service.ts:1087`)
- รายชื่อที่ส่งกลับมีแค่ชื่อ-สกุล เลขสมาชิก โรงเรียน กลุ่ม และยอด — ไม่มีเลขบัตรประชาชน จึงไม่ต้อง
  ผ่าน `applyIdCardMask`
- จำกัดขนาดไฟล์ที่รับไว้ 5 MB กัน payload ใหญ่ผิดปกติ

## 8. เกณฑ์ว่าสำเร็จ

1. อัปโหลดไฟล์ที่ลบแถวทิ้ง แล้วระบบขึ้นรายชื่อคนที่หายครบถ้วน ไม่เงียบอีกต่อไป

3. อัปโหลดไฟล์ .xlsx จริง แล้วอ่านได้ ไม่ใช่ข้อมูลขยะ
4. รายชื่อที่ขาดดาวน์โหลดเป็น .xlsx เปิดด้วย Excel ได้
5. การแจ้งเตือนที่ตัดสมาชิกภาพได้ ไม่เกิดขึ้นเองโดยไม่มีการยืนยันจากผู้ใช้
